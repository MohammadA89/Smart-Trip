# Smart Trip

Smart Trip یک وب‌اپلیکیشن پیشنهاد مقصد با Flask است که بر اساس موقعیت مکانی یا نام شهر، نوع فعالیت، بودجه، تعداد افراد، نوع گروه و دسترسی به خودرو، پنج مکان مناسب را رتبه‌بندی و روی نقشه نمایش می‌دهد.

این پروژه برای دریافت اطلاعات مکان‌ها از [OpenStreetMap](https://www.openstreetmap.org/)، Nominatim و Overpass استفاده می‌کند. اگر سرویس‌های بیرونی در دسترس نباشند یا نتیجه کافی برنگردانند، برنامه به‌صورت خودکار از داده‌های آزمایشی داخلی استفاده می‌کند تا رابط کاربری همچنان قابل استفاده باشد.

## قابلیت‌ها

- جست‌وجوی مکان‌های نزدیک بر اساس مختصات و شعاع ۱ تا ۱۵ کیلومتر
- جست‌وجو در محدوده یک شهر با تبدیل نام شهر به مختصات
- پیشنهاد مکان در چهار دسته طبیعت، کافه، رستوران و سرگرمی
- شخصی‌سازی نتایج با توجه به بودجه، نوع گروه، تعداد افراد و خودرو
- رتبه‌بندی پنج پیشنهاد برتر همراه با امتیاز و دلیل پیشنهاد
- نمایش نتایج روی نقشه و ارائه مسیر در سرویس نقشه
- رابط کاربری فارسی و انگلیسی
- دریافت ترجیحات از طریق فرم یا چت متنی ساده
- یادگیری تدریجی از کلیک و انتخاب کاربر، به‌صورت عمومی و مخصوص هر نشست
- ذخیره پیشنهادها، بازخوردها و وزن‌های مدل در SQLite
- کش کوتاه‌مدت درخواست‌های OpenStreetMap و fallback به داده‌های آزمایشی

## پیش‌نیازها

- Python 3.9 یا جدیدتر
- دسترسی اینترنت برای دریافت داده‌های واقعی OpenStreetMap
- مرورگر مدرن

برای حالت آزمایشی، برنامه بدون دسترسی به OpenStreetMap نیز اجرا می‌شود؛ در این حالت نتایج از داده‌های داخلی تولید می‌شوند.

## اجرای سریع در ویندوز

در PowerShell و از ریشه پروژه اجرا کنید:

```powershell
.\run.ps1
```

این اسکریپت در صورت نیاز محیط مجازی `.venv` را می‌سازد، وابستگی‌ها را نصب می‌کند و سرور را در آدرس زیر بالا می‌آورد:

```text
http://127.0.0.1:5000
```

اگر PowerShell اجرای اسکریپت را محدود کرد، فقط برای همان نشست از دستور زیر استفاده کنید:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\run.ps1
```

## نصب و اجرای دستی

### ویندوز (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python app.py
```

### Linux و macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python app.py
```

سپس `http://127.0.0.1:5000` را در مرورگر باز کنید. برای توقف سرور در ترمینال `Ctrl+C` را بزنید.

> اجرای فعلی `python app.py` برای توسعه محلی است و Flask را با debug mode اجرا می‌کند. برای محیط production از یک WSGI server واقعی استفاده کنید و debug mode را غیرفعال نگه دارید.

## نحوه استفاده

1. حالت جست‌وجو را روی «نزدیک من» یا «کل شهر» قرار دهید.
2. در حالت نزدیک، اجازه دسترسی مرورگر به موقعیت مکانی را بدهید یا از موقعیت پیش‌فرض استفاده کنید؛ در حالت شهر، نام شهر را وارد کنید.
3. نوع گروه، بودجه، فعالیت، تعداد افراد، خودرو و شعاع را مشخص کنید.
4. درخواست پیشنهاد را ارسال کنید.
5. یکی از پنج نتیجه را روی نقشه بررسی یا انتخاب کنید. انتخاب‌های کاربر برای بهبود رتبه‌بندی‌های بعدی همان نشست استفاده می‌شوند.

همچنین می‌توانید در بخش چت عبارتی مانند نمونه‌های زیر بنویسید:

```text
کافه دنج توی تهران با بودجه کم
پارک نزدیک در شعاع ۵ کیلومتر برای خانواده
cozy cafe in Tehran with low budget
```

چت یک مدل زبانی نیست؛ یک parser قاعده‌محور است که ترجیحات قابل تشخیص را از متن استخراج و روی فرم اعمال می‌کند.

## سیستم پیشنهاددهی چگونه کار می‌کند؟

1. نام شهر با Nominatim به مختصات و محدوده تبدیل می‌شود، یا مختصات مرورگر به‌عنوان مبدأ در نظر گرفته می‌شود.
2. مکان‌های مرتبط از Overpass بر اساس دسته فعالیت دریافت می‌شوند.
3. برای هر مکان ویژگی‌هایی مانند تطابق فعالیت، فاصله، تناسب گروه، بودجه، تعداد افراد، کیفیت و محبوبیت محاسبه می‌شود.
4. مدل رتبه‌بندی خطی نسخه `ml-v3` به هر گزینه امتیاز می‌دهد و پنج نتیجه برتر را انتخاب می‌کند.
5. بازخوردهای `click`، `choose` و `like` با یک به‌روزرسانی pairwise وزن‌های عمومی و وزن‌های مخصوص نشست را اصلاح می‌کنند.
6. در خطای شبکه یا کمبود نتیجه، داده‌های آزمایشی جایگزین یا تکمیل‌کننده نتایج می‌شوند.

منبع داده در پاسخ API با یکی از مقادیر `osm`، `demo` یا `osm+demo` مشخص می‌شود.

## API

همه endpointهای کاربردی JSON دریافت و برمی‌گردانند.

### بررسی سلامت

```http
GET /health
```

پاسخ موفق:

```json
{"status": "ok"}
```

### دریافت پیشنهاد

```http
POST /recommend
Content-Type: application/json
```

نمونه درخواست جست‌وجوی نزدیک:

```json
{
  "session_id": "demo-user-1",
  "lang": "fa",
  "search_mode": "radius",
  "lat": 35.6892,
  "lon": 51.389,
  "radius_m": 5000,
  "activity": "nature",
  "group_type": "family",
  "budget": "medium",
  "people_count": 4,
  "has_car": true
}
```

برای جست‌وجوی شهری، `search_mode` را برابر `city` قرار دهید و فیلد `city` را ارسال کنید:

```json
{
  "session_id": "demo-user-1",
  "lang": "fa",
  "search_mode": "city",
  "city": "Tehran",
  "activity": "cafe",
  "group_type": "friends",
  "budget": "low",
  "people_count": 3,
  "has_car": false
}
```

مقادیر اصلی ورودی:

| فیلد | مقادیر یا توضیح |
| --- | --- |
| `search_mode` | `radius` یا `city` |
| `activity` | `nature`، `cafe`، `restaurant` یا `entertainment` |
| `group_type` | `solo`، `friends` یا `family` |
| `budget` | `low`، `medium` یا `open` |
| `radius_m` | بین ۱۰۰۰ تا ۱۵۰۰۰ متر |
| `lat`, `lon` | مختصات مبدأ در حالت شعاعی |
| `city` | نام شهر در حالت شهری |
| `session_id` | شناسه اختیاری برای شخصی‌سازی نتایج |

پاسخ شامل `request_id`، مبدأ، منبع داده و آرایه `recommendations` است. هر پیشنهاد اطلاعاتی مانند `place_id`، مختصات، فاصله، امتیاز، breakdown امتیاز و توضیح رتبه‌بندی دارد.

### ثبت بازخورد

```http
POST /feedback
Content-Type: application/json
```

```json
{
  "request_id": "REQUEST_ID_FROM_RECOMMEND",
  "place_id": "osm:node:123456",
  "session_id": "demo-user-1",
  "action": "choose"
}
```

اکشن‌های `click`، `choose` و `like` باعث آموزش مدل می‌شوند. اکشن‌های دیگر فقط به‌عنوان event ذخیره می‌شوند.

### پردازش پیام چت

```http
POST /chat
Content-Type: application/json
```

```json
{
  "session_id": "demo-user-1",
  "lang": "fa",
  "message": "رستوران خانوادگی در تهران با بودجه متوسط",
  "current": {
    "search_mode": "radius",
    "activity": "nature"
  }
}
```

پاسخ شامل متن کوتاه `reply` و فیلد `updates` برای به‌روزرسانی فرم است.

## ساختار پروژه

```text
Smart-Trip-main/
├── app.py                         # نقطه ورود توسعه محلی
├── run.ps1                        # نصب و اجرای سریع در ویندوز
├── requirements.txt               # وابستگی‌های Python
├── instance/                      # دیتابیس محلی تولیدشده (در Git ذخیره نمی‌شود)
└── smarttrip/
    ├── app.py                     # application factory و routeها
    ├── algorithm.py               # داده‌های آزمایشی و محاسبات پایه
    ├── ai_recommender.py          # استخراج ویژگی، امتیازدهی و یادگیری
    ├── chat_parser.py             # استخراج ترجیحات از متن
    ├── storage.py                 # schema و عملیات SQLite
    ├── services/
    │   └── osm_service.py         # ارتباط با Nominatim و Overpass
    ├── templates/
    │   └── index.html             # صفحه اصلی
    └── static/
        ├── css/style.css
        └── js/main.js
```

برنامه از الگوی application factory استفاده می‌کند و نمونه Flask از طریق `smarttrip.app:create_app` قابل import است.

## داده‌های محلی

در اولین درخواست، SQLite به‌صورت خودکار در مسیر زیر ساخته می‌شود:

```text
instance/smarttrip.sqlite
```

این دیتابیس شامل وزن‌های عمومی، وزن‌های مخصوص نشست، درخواست‌های پیشنهاد، آیتم‌های پیشنهادشده و eventهای کاربر است. فایل‌های دیتابیس و log در `.gitignore` قرار دارند و نباید commit شوند.

برای پاک‌کردن تاریخچه و بازنشانی وزن‌های یادگرفته‌شده، ابتدا سرور را متوقف و سپس فایل دیتابیس را حذف کنید. در اجرای بعدی schema و وزن‌های اولیه دوباره ساخته می‌شوند.

## تست و بررسی سلامت

پس از اجرای سرور:

```powershell
Invoke-RestMethod http://127.0.0.1:5000/health
```

یا در Linux/macOS:

```bash
curl http://127.0.0.1:5000/health
```

در حال حاضر مجموعه تست خودکار در پروژه وجود ندارد. پیش از تغییرات بزرگ، حداقل import برنامه، endpoint سلامت، رتبه‌بندی، parser چت و fallback شبکه باید بررسی شوند.

## محدودیت‌های فعلی

- کیفیت و پوشش نتایج واقعی به داده‌های OpenStreetMap در منطقه موردنظر وابسته است.
- Nominatim و Overpass سرویس‌های عمومی با محدودیت نرخ و احتمال timeout هستند.
- امتیاز، قیمت و محبوبیت بعضی مکان‌ها تخمینی است، چون OSM همیشه این داده‌ها را ارائه نمی‌کند.
- یادگیری فعلی سبک و آنلاین است و جایگزین یک سامانه توصیه‌گر آموزش‌دیده با داده‌های واقعی نیست.
- SQLite برای اجرای محلی مناسب است؛ برای بار هم‌زمان بالا باید از دیتابیس و معماری production استفاده شود.
- چت مبتنی بر قواعد و کلمات کلیدی است و همه عبارت‌های طبیعی را درک نمی‌کند.

## امنیت و استقرار

- هیچ کلید API برای سرویس‌های فعلی لازم نیست و نباید secret یا فایل `.env` را commit کرد.
- ورودی‌های API باید در مرز route اعتبارسنجی شوند و queryهای دیتابیس باید پارامتری باقی بمانند.
- در production از debug server داخلی Flask استفاده نکنید.
- برای استفاده عمومی، rate limiting، لاگ ساختاریافته، مدیریت خطا، HTTPS و محدودسازی اندازه requestها اضافه کنید.
- پیش از مقیاس‌دهی، درخواست‌های بیرونی را پشت cache پایدار و سیاست retry کنترل‌شده قرار دهید.
